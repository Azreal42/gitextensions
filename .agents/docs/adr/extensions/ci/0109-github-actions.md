# ADR 0109 · Lecture CI GitHub Actions

Décision : un fournisseur Actions en lecture seule, désactivé par défaut. Pages CI et GitHub Actions N2 ; [périmètre](../../../todo.md#contributeurs-console-liens-et-github-actions--validation-ciblée).

Les clés XML Windows `BuildServer.*` et `BuildServer.GitHub Actions.*` utilisent les scopes et la baseline acquittée communs ([ADR0105](../../preferences/detailed/0105-detailed-graph-and-xml-settings.md)). Apply publie les changements ; Cancel abandonne le reste. Détection owner/repository sans écriture ; token masqué, explicite et stocké dans le fichier choisi. Aucun coffre ou dialogue générique de credentials n’est déduit de ce champ.

`GitHubActionsApiClient` fait seulement GET : pages numériques de 100, borne explicite, ETag/304 et cache 30 s ; aucune publication partielle après erreur/annulation. Les workflows frères restent distincts par SHA ; états Windows et inconnus conservés. Le token exige HTTPS, reste lié à l’origine configurée et n’est transmis ni par Link ni vers une redirection d’autre origine ; erreurs affichées fixes sans payload/secret. `MainWindow.GitHubActions` possède polling/rafraîchissements et drainage à Close. L’ancien rendu Linux affichait une liste locale des runs et ouvrait leur page sur geste explicite. Le parcours Windows GitHub Actions, ShowInBuildReportTab=false, attend un lien Open report centré plutôt qu’un viewer HTML ; ce contrat et le résultat représentatif commun sont repris par [ADR0136](0136-windows-build-report.md), avec qualification distincte.

Jobs/logs et mutations de workflow ne font pas partie de ce parcours Windows GitHub Actions ; leur absence n’est donc pas une fenêtre manquante à porter. Les PR et les autres fournisseurs gardent leurs parcours distincts ; leur mode HTML true reste partiel. Tests HTTP contrôlés, lecture anonyme, interface live authentifiée/Enterprise, natif et paquet exigent leurs preuves propres.
