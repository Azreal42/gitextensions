# ADR 0033 · Menu et fenêtre Stash

Statut : accepté et livré pour le menu et les fenêtres de base, source 36aae198f467312e5846919b8c4069967d804b04.

La capture Windows et FormBrowse/FormStash définissent le bouton scindé et la fenêtre. Le segment principal ouvre Manage stashes ; le dropdown est ancré sur son bord gauche et reprend Stash, Stash pop, séparateur, Manage stashes, Create a stash. Stash staged est visible avec Git >= 2.35, comme le source Windows actuel. Le triangle 6×3 est partagé avec les autres indicateurs. Le débordement du toolbar conserve ces actions.

Ctrl+Alt+Up enregistre immédiatement les changements, sans demande de message et sans Keep index ; Include untracked vient du réglage persistant, faux par défaut comme Windows. Ctrl+Alt+Down applique et supprime le dernier stash, indépendamment du graphe ou de la sélection. Ctrl+Shift+Alt+Up enregistre uniquement l’index. Ces touches fonctionnent aussi depuis le popup. Les contrôles Stash sont désactivés sur un bare.

Une seule fenêtre native reprend les deux modes FormStash : Manage sélectionne le premier stash s’il existe, Create sélectionne les changements courants. À gauche : Show, FileStatusList original partagé avec groupes Index/Workspace, message, Keep index et Include untracked, puis Stash all/selected, Drop et Apply. À droite : FileContentView/DiffView partagés, palettes, images, codecs, options de comparaison et recherche. Le splitter est réglable ; les légendes, mnémoniques et infobulles viennent des XLF originaux. Le message reprend le fond Info. Les options se mémorisent dans stash-preferences.json XDG ; les légendes longues françaises restent visibles.

Les fichiers sélectionnés sont transmis littéralement avec :(literal), sans global literal-pathspecs qui casserait le nettoyage interne des fichiers non suivis. Renommages partiels : même contrat que git stash push -- <nouveau nom> original ; Git peut conserver la suppression indexée de l’ancien nom. Aucun reset supplémentaire implicite. Les aperçus du stash lisent le diff premier parent et le troisième parent des fichiers non suivis ; les patches/chemins NUL et octets binaires sont conservés. Le message complet utilise %B, car %s aplatit les retours à la ligne.

Apply conserve le stash ; Apply/Pop passent sans --index, comme Windows. Drop confirme avec No par défaut et une suppression volontaire persistante de la confirmation ; il sélectionne ensuite le stash voisin. Une sélection devenue obsolète est refusée avant Apply/Pop/Drop pour éviter de viser le nouveau stash@{n}. Les mutations sont sérialisées ; les erreurs et annulations restent visibles. Les opérations tentées rafraîchissent Browse ; un pop en conflit conserve le stash, ouvre la gestion des changements et permet la résolution/staging dans PatchConflictDialog, sans inventer une opération merge à continuer/abandonner.

F5 rafraîchit ; Ctrl+N/Ctrl+P parcourent les stashes dans l’ordre original. Échap ferme le dropdown, désélectionne le texte du viewer/champ, puis ferme la fenêtre ; fermer pendant une commande annule Git et ses descendants. Les anciennes APIs StashAsync/ApplyStashAsync restent compatibles pour les autres appelants ; les entrées Browse utilisent les nouvelles options/identités typées.

Validation locale : huit nouveaux scénarios Core Git réels, 155/155 scénarios Core ; treize parcours UI/Git, 13/13 sans ignoré. Menu/pointeur/clavier, les deux modes, messages saisis, chemins littéraux et renommages, fichiers non suivis, index, aperçus, Apply/Pop/Drop, No/Yes et préférence, français/clair/sombre, bare, état vide, résolution réelle et cancellation du processus. Six projets Release sans diagnostic. Les essais de calibration restent dans artifacts/linux/stash-development-tests ; ils ne sont pas les preuves du paquet final. Le reste de la migration et les fonctions contextuelles avancées des listes restent ouverts.
