# ADR 0032 · Menu Pull/Fetch original

Statut : accepté et livré pour le périmètre du menu, source 94f44d78fdb430f0ae3e89a80883cfa69dd65412.

La capture du menu Windows et FormBrowse/FormPull définissent l’ordre, les icônes et les six actions. Un bouton scindé compact reprend l’action principale et son dropdown, ancré sur le bord gauche du bouton comme Windows ; le même menu reste accessible dans le débordement de Browse. Le sous-menu Set default Pull button action reste ouvert, coche exclusivement le choix et n’exécute aucun Git. Les légendes et touches d’accès viennent des XLF existants ; GitPullAction est partagé directement depuis le fichier original.

DefaultPullAction et FormPullAction restent distincts, Merge par défaut comme l’original. pull-preferences.json dans XDG enregistre le défaut du bouton, le dernier mode du dialogue et la suppression volontaire de la confirmation FetchPruneAll. F8 et le bouton exécutent le défaut, Ctrl+Down ouvre le dialogue ; Ctrl+Shift+Down est le QuickFetch natif sans remote/refspec, Ctrl+Shift+P lance Merge. FetchAll disparaît dans les deux menus à zéro/un remote, sans remplacer un défaut déjà enregistré.

Le menu rapide utilise le remote de la branche checkoutée, ou le premier remote réel si absent/invalide ; le graphe sélectionné ne le change pas. Le champ de branche distant reste vide initialement. Fetch, FetchAll et FetchPruneAll sont distincts ; les fetchs ordinaires gardent fetch.prune/tagopt configurés. PruneAll ajoute --all --prune --force, sans --prune-tags, et demande confirmation avant commande. Les anciens FetchAsync/PullAsync restent compatibles pour leurs autres appelants.

Merge utilise --no-rebase afin que son mode visible reste explicite sur les Git récents ; contrairement au plain pull original, pull.rebase ne peut plus le convertir en rebase. Le Git installé fait également primer --no-rebase sur pull.ff=only : Merge réapplique donc --ff-only lorsqu’il est configuré, pour conserver cette restriction historique. Rebase passe --rebase et conserve la priorité native sur pull.ff, mesurée par un oracle Git direct. Aucun réglage Git n’est réécrit.

PullDialog expose remote/branche littéraux, Merge/Rebase/Fetch et pruning. Les erreurs affichent les deux flux Git ; les conflits permettent résolution, continuation ou abandon. Les opérations tentées rafraîchissent Browse même après erreur/annulation. Le token de l’opération Main couvre l’initialisation et l’exécution du dialogue ; une annulation rapide n’ouvre pas de dialogue de repli. Le choix [ All ] force Fetch. La confirmation du rebase d’un merge garde No par défaut, sans lancer de Merge. Les raccourcis globaux fonctionnent aussi depuis les racines popup, notamment F8 dans le sous-menu de défaut. Bare autorise Fetch ; les raccourcis Merge/Rebase ne deviennent pas des fetchs. HEAD détaché offre checkout/continuer/annuler, un remote différent exige une branche ou confirmation, et les wildcards sont refusés pour Pull. Les options avancées du FormPull complet restent dans le suivi global.

Validation : douze scénarios Core réels (deux bare locaux sans origin, upstream non premier, portée/prune/tags/config, divergence, politiques Git, erreurs et annulation avec descendants) ; dix-sept scénarios UI/Git (menus/pointeur/clavier, préférence après réouverture, français/thèmes, branches, confirmations, résolution/abort, bare/détaché). Core 147/147, UI ciblée 17/17 et six projets Release sans avertissement/erreur (pull-menu-core-147-apphost-local.log, pull-radio-user-input-02.log). Les attentes All branches contrôlent le marqueur HEAD plutôt que l’ordre temporel des commits distants. Les logs de calibration et de lancement erronés sont conservés ; aucune commande ne vise les remotes du dépôt utilisateur.
