# ADR 0162 · Suite Plugins sur les hôtes natifs

Statut : 42/42 qualifiés sur les deux Mac au commit `a0f471f40` ; correctifs Windows en qualification. [Objectif trois plateformes](0159-avalonia-three-platforms.md), [supervision POSIX](0161-posix-process-lifecycle.md). Aucun changement produit ou de thème dans les fixtures.

Les 42 scénarios Plugins gardent leurs noms et assertions métier. Un vrai apphost .NET, copié sous le nom de l’exécutable configuré, remplace les scripts Python Linux : argv littéraux, répertoire, PID journalisé, sorties, code 7, attente et annulation sont observés à la frontière du processus. Le profil Git est un fichier privé et les hooks un répertoire vide ; aucun `/dev/null` ni Python système n’est nécessaire.

Les noms non représentables sur NTFS restent de vrais blobs/arbres Git préparés par `hash-object`/`update-index`, sans réécriture de leurs octets. CE_VALID est posé à l’insertion. Renommages, copies et chemins binaires de GitImpact gardent tous leurs délimiteurs opaques. LOC nécessite un fichier réel : Windows utilise un nom valide avec caractères littéraux, et garde aussi l’entrée HEAD originale impossible à matérialiser, explicitement vérifiée. La solution de compilation conserve des crochets et du texte ressemblant à une commande ; seul l’astérisque interdit par NTFS varie. Pour les notes de version, les guillemets, tabulations, sauts de ligne, accolades et Unicode restent présents sous Windows ; l’antislash, séparateur de Git Windows, demeure dans le cas POSIX. Aucun préfixe magique ne remplace le chemin : le dépôt utilise déjà les pathspecs littéraux.

L’annulation des notes de version vise toujours un véritable `git log` : ouverture FIFO bloquée sur POSIX ; canal Trace2 Windows sans lecture du serveur, avec taille et octets en attente vérifiés par le noyau. `cmd/git.exe` étant un lanceur, la fixture sélectionne le vrai binaire voisin de `--exec-path` ; son PID doit être le client authentifié du pipe. L’image Git et sa référence stable (handle, pidfd ou kqueue) doivent être vivantes avant annulation et arrêtées avant son retour ; l’instantané intégral du dépôt reste identique.

Validation locale finale : compilation sans avertissement/erreur, 42/42 scénarios et identités antérieures conservées. Le premier passage 41/42 détectait des fichiers absents du worktree après préparation de l’index ; la matérialisation corrige la fixture sans retirer le contrôle d’état propre. [CI native `a0f471f40`](https://github.com/Azreal42/gitextensions/actions/runs/41728467879) : les deux Mac passent 42 Plugins, six contrats noyau et 151 Desktop chacun, avec archives/backend ; Windows révèle cinq erreurs de préparation (37/42), corrigées dans ce lot. Les contrôles Windows renforcés doivent encore passer nativement. Résultats : `artifacts/cross-platform/20261103/plugin-portability-*` et `process-exit-events`.

La CI native exécute la suite entière sans filtre et publie son journal ; le workflow Linux complet reste en place. Les 151 contrats Desktop natifs restent un sous-ensemble ; suites Core/Desktop complètes Windows/macOS et console interactive/PTY/IPC restent ouvertes. [Attentes de sortie](0163-process-exit-notifications.md).

Repères : [Trace2 Git](https://github.com/git/git/blob/master/trace2/tr2_dst.c), [named pipes Git for Windows](https://github.com/git-for-windows/git/blob/main/compat/mingw.c), [index-info](https://github.com/git/git/blob/master/builtin/update-index.c).

Second passage Windows au commit `ed1161b8c` : 41/42 ; le vrai PID est désormais correct, mais la première connexion est déjà fermée lors du contrôle des octets (erreur 109). La fixture prépare plusieurs instances asynchrones, remplace les connexions transitoires fermées et ne valide que le client qui garde de vraies données non lues. Le PID et la quantité de données restent exigés ; DisposeAsync ferme et attend tous les connecteurs privés. La suite Linux reste à 42/42 après ce changement ; nouveau passage Windows requis.
