# ADR 0159 · Avalonia sur Windows, Linux et macOS

Statut : en cours. Objectif : rendre la même application Avalonia utilisable sur les trois systèmes, avec le comportement et les éléments visuels partagés de Git Extensions. Une compilation ou un smoke test ne prouve pas la parité de tous les workflows.

Décisions :

- Garder Core, Desktop, Plugins et les styles communs. Le nom historique `src/linux` ne limite pas la cible .NET. Propager le RID dans les références de projets : Core transporte un lanceur natif et ne doit pas devenir implicitement indépendant du RID.
- Centraliser les associations fichiers/liens dans `DesktopResourceLauncher` : ShellExecute Windows, `open` macOS, `xdg-open` Linux. Cibles en données, journal de processus existant conservé.
- Respecter la casse native des variables d’environnement. Quoter les chemins d’éditeur pour le shell de Git, y compris Git for Windows ; aucun message ou plan ne devient une commande shell.
- Windows : helper askpass `.exe` autonome, protocole stdout recopié sans transcodage ni diagnostic. macOS/Linux : helper Unix voisin de l’exécutable. Le contrôle DISPLAY reste propre à Linux.
- Livraisons autonomes Windows et bundles `.app` Intel/Apple Silicon via `eng/desktop/`. Vérifier l’architecture, les empreintes de l’archive extraite, le runtime embarqué et le vrai backend graphique sur les runners natifs. Les bundles alpha macOS ont une signature ad hoc ; aucune notarisation n’est annoncée.

Preuves initiales : compilation locale sans avertissement/erreur, 56 tests Desktop ciblés, dont vrais dépôts Unicode/espaces/apostrophes, rebase avec le véritable éditeur déplacé et clic/flèche conservant focus et objets de grille. Une archive Windows PE x64 complète a été construite et contrôlée depuis Linux : ce contrôle statique ne prouve pas son exécution Windows. Références dans `artifacts/cross-platform/20261103/`. Le premier essai de publication a correctement échoué sur un helper Linux transitif ; la propagation explicite du RID corrige ce cas.

Les premiers jobs natifs ont révélé deux défauts corrigés : normalisation des chemins Git for Windows dans les journaux de rebase et sélection de l’ABI Darwin `lstat$INODE64`/`fstat$INODE64` sur Intel. Les 70 contrats passent ensuite sur Windows, macOS Intel et Apple Silicon (run `41650512897`). Windows vérifie aussi son archive et démarre le backend natif. La signature Mac a révélé les notices versionnées placées dans un emplacement de code : elles sont désormais dans `Contents/Resources`, avec vérification récursive après extraction ; cette livraison reste à qualifier sur les runners.

Les jobs `Avalonia native platforms` exécutent les premiers contrats portables, les dialogues askpass headless puis le vrai programme publié. La suite Linux complète reste indépendante. Les suites Windows/macOS complètes, encore liées à des fixtures Unix, restent à porter sans remplacer leurs assertions métier par des tests plus faibles.

Le contrôle de livraison askpass rejette seulement les arguments en excès : une invite omise est valide selon le contrat OpenSSH déjà testé. Le helper Windows transmet aussi cette invocation au dialogue par défaut, sans confondre absence et chaîne vide. Les 143 tests locaux ciblés passent ; les contrôles de signature et d’empreintes du bundle Mac extrait ont passé sur Intel avant ce défaut du vérificateur.

La recherche de mises à jour choisit le `.deb` Linux ou l’archive Windows/macOS correspondant à l’architecture native ; elle garde les contrôles des URI, tailles et empreintes. Les 92 tests locaux ciblés passent, dont 13 contrats de sélection et téléchargement portables. Le test de mise à jour via Settings attend maintenant le chargement asynchrone avant son clic réel sur Apply. Le premier run Linux de cette série (`41646245616`) a passé toute la suite et publié son `.deb`.

La préservation explicite des journaux orphelins emploie `renameat2(RENAME_NOREPLACE)` sous Linux, `renamex_np(RENAME_EXCL)` sous macOS et `MoveFileExW` sans remplacement/copie sous Windows. Les tests portent sur l’entrée déplacée (fichier, dossier, lien valide ou cassé), les octets de sa cible et l’identité du checkout ; 47 tests locaux ciblés passent. La qualification Windows/macOS de cette nouvelle primitive reste confiée aux jobs natifs.

La revue de la capture native Mac Intel a montré un repli arbitraire sur une police à empattements malgré des tests fonctionnels verts. Les replis ajoutent Helvetica Neue/Arial pour l’interface et Menlo/Monaco/Courier New pour le code ; les rôles de secours à chasse fixe sont vérifiés par les métriques réelles. Les préférences Segoe UI/Consolas enregistrées restent intactes. Les 207 tests locaux ciblés, dont les contrôles de polices existants, passent. Les nouveaux jobs natifs couvrent 131 cas, sans annoncer la suite complète Windows/macOS.

GitHub a annulé les jobs ARM des runs `41656633912` et `41657405557` avant allocation, avec le diagnostic explicite de manque de capacité des runners macOS arm64. La matrice conserve Intel sur macOS 15 et utilise l’image standard Apple Silicon `macos-26` ; les mêmes tests, signatures, archives et backend restent bloquants. Un résultat de provisioning n’est pas compté comme un test exécuté.

Le [run natif `41660089091`](https://github.com/Azreal42/gitextensions/actions/runs/41660089091) a passé 131/131 cas sur les trois systèmes, livré les trois archives et démarré les trois backends ; la capture Mac corrigée a été revue. Les jobs ARM macOS 15 avaient enfin obtenu une machine. La qualification du commit courant avec macOS 26 reste distincte.

La résolution des exécutables configurés Windows/macOS utilise maintenant le PATH capturé, sans mutation du parent ni repli sur un autre Git ambiant. Deux nouveaux tests utilisent un vrai apphost déplacé dans un chemin Unicode. Le run Linux `41653051059` a aussi exposé un key-up envoyé après destruction du backend headless ; deux parcours de fermeture similaires sont corrigés, avec toutes les assertions de focus, visibilité, identité et drainage conservées. Les 167 tests locaux combinés passent ; les 133 contrats natifs et les suites Linux complètes restent à requalifier sur cette dernière source.

La CI Linux `41663702574` a révélé la publication d’un avatar après fermeture pendant la propagation asynchrone des tokens. L’admission et la publication des consommateurs vérifient le propriétaire et l’appelant sous le verrou de fermeture, pour les lectures possédées comme empruntées. Deux nouveaux cas déterministes sont rouges sur l’ancien code ; les 174 cas combinés passent avec la correction. Les 17 tests AvatarService sont maintenant des contrats CrossPlatform : le sous-ensemble natif atteint 150 cas, sans remplacer les suites complètes.

Les signaux natifs des fixtures ne deviennent visibles qu’après fermeture de leurs données PID, via renommage atomique dans le même dossier. Les attentes Settings portent sur le contrôle effectivement disponible ; le test askpass isole le profil utilisateur et restaure ses cultures. Les menus utilisent le pilote de clic strict partagé. Les 240 scénarios concernés passent ; les nouvelles suites Linux (4 624 Desktop) et les trois livraisons restent soumises aux jobs du commit exact. La deuxième tentative ARM `41663703052` a encore échoué avant allocation, pour manque de capacité GitHub ; aucune assertion n’a été exécutée sur ce job.

L’audit des protocoles de signalisation a trouvé un dernier lecteur Index qui attendait seulement la création du fichier. Il utilise maintenant le même renommage après fermeture ; les sept scénarios d’historique concernés passent. Les autres lecteurs attendent un signal distinct, un contenu non vide écrit en une fois ou un couple de PID décodable. La matrice ARM revient à l’image standard macOS 15, minimum déclaré du bundle et image du run ARM déjà qualifié `41660089091` ; les dernières tentatives macOS 26 sont restées sans allocation. Les 150 contrats, la signature et le backend restent les mêmes contrôles bloquants.

Écarts techniques encore ouverts : console interactive (`script`, sockets/pidfd Linux), terminaux Windows/macOS et environnement capturé, verrous interprocessus macOS et cycle de vie des descendants hors Linux. Restent également la qualification native des dialogues/menus, raccourcis macOS, haute résolution et parcours d’authentification réels. Les modifications Modal/README/docs préexistantes du primaire ne font pas partie de cette source isolée.
