# ADR 0140 · Cache réel des commandes

Retrouver CommandCache et le second onglet de FormGitCommandLog Windows avec de vrais résultats réutilisés. L’admission est explicite dans les lecteurs immuables du dépôt, sans préférence utilisateur supplémentaire ni cache général du Runner. Cache global au processus, 50 entrées, éviction LRU ; l’inspection touche la récence sans déplacer les lignes. Succès 0 et résultat objet validé seulement ; copies des octets pour les consommateurs. Bornes : 8 MiB bruts stdout + stderr par entrée et 64 MiB de contributions retenues, chaînes comprises ; ce ne sont pas des limites de RSS. Refuser un dépassement sans tronquer la sortie.

Partitionner par dépôt effectif, environnement figé, arguments, stdin et dépendances vérifiées. Git découvre config/includes et origines ; les hits valident les identités et contenus FS, liens, graphe/replace/shallow/grafts et outils concernés. Séparer les autorités brutes des lecteurs dépendant des attributs ; exécuter énumérations et hashes hors UI, avec annulation et bornes. Suivre les overrides natifs, y compris les cibles absentes ; chemins relatifs graft/shallow admis seulement à la racine native. Une autorité non vérifiable impose une lecture fraîche, sans erreur ajoutée au lecteur.

Admettre les souslectures immuables de commit, objets/arbres/blobs, graphe, diff/range/combined, grep et Blame, et Difftastic simple dont l’exécutable est fermé. Notes/mailmap, références mobiles, index/worktree et Recovery/fsck restent frais ; le show composite avec notes n’est pas recomposé. Blame avec textconv non fermé et DFT avec expansions shell non fermées bypassent. Un hit valide évite le processus cible et n’invente aucune ligne dans le journal ; le bootstrap ou une autorité invalidée peuvent encore lancer leurs vraies sondes Git.

Recovery emploie une API de prévisualisation fraîche et conserve son erreur si l’objet Git disparaît ; les aperçus génériques gardent leur cache. Ce correctif conserve le contrat portable sans attribuer cette fraîcheur à Windows. Les scripts Git aux lectures externes non fermées sont refusés par le cache, même si leur fichier, leurs arguments et leur environnement sont inchangés.

L’onglet cache affiche les véritables clés et sorties admises, séparées du journal sécurisé de métadonnées. PrintableChars Windows rend visibles NUL/CR/LF/TAB/espace/ESC ; il ne masque pas les données. Clear/Ctrl+L est indépendant par onglet : vider le cache ne vide pas le journal et une lecture déjà en vol peut réadmettre son résultat. Liste/détail, fontes/wrap et sélection par Id sont conservés ; aucun export cache inventé. Les arguments et sorties de cet onglet ne sont pas ajoutés au journal ni à son export sûr.
