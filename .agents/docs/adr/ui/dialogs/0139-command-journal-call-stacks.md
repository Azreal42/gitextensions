# ADR 0139 · Piles opt-in et thread appelant du journal

Compléter le [journal ADR0138](0138-command-journal-lifecycle.md) avec le diagnostic portable Windows, sans ouvrir les canaux de données brutes. La case Capture call stacks sauvegarde immédiatement `Log.CaptureCallStacks`, false par défaut, dans le global XDG `GitExtensions.settings`. Lire sans créer ; conserver les clés étrangères et refuser une autorité corrompue ou périmée, avec diagnostic et réouverture explicite. Utiliser le writer XML partagé et ordonner son CAS avec la publication runtime, sans réécrire un ancien profil General/Advanced.

Figer le choix, la pile et le bool UI au point d’appel synchrone, avant l’attente askpass ; conserver ce contexte dans les états lancement/PID/fin. Le bool décrit le thread appelant, pas un blocage de l’interface. La sonde Desktop est indépendante de l’option de pile ; sans dispatcher confirmé, la valeur reste inconnue. Le Core ne dépend pas du Desktop. Désactiver évite la projection pour les lancements suivants, sans effacer les anciennes lignes.

Ne retenir que les noms type/méthode des objets Assembly Core/hôte approuvés, avec types génériques de définition. Exclure symboles dynamiques/inconnus, chemins et lignes source, arguments/valeurs, environnement, entrées/sorties et erreurs brutes. Borne : 32 frames, 256 caractères par frame, 4096 caractères par pile, marqueurs compris, dans les 500 entrées existantes ; cela ne borne pas les allocations transitoires ou le CPU. Les détails et l’export explicite portent ce texte sûr ; Copy reste le descripteur de commande.

Une écriture acquise et sa publication s’achèvent hors dispatcher, même si le journal ferme. Le bootstrap draine leur porte après la fin de la boucle UI ; aucune continuation UI n’est nécessaire pour terminer le processus. Les annulations avant effet n’annoncent aucune sauvegarde. Cache réel, autres processus, taille/position et données brutes Windows restent distincts.
