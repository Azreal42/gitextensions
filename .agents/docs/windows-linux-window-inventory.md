# Inventaire Windows → Linux et niveau de portage

Référence du code : `aca93bcead051ee9e65822c09beeae003d0da74c`. Recensement du 16 octobre 2026 ; 1863 fichiers C# du checkout analysés avec Roslyn (suivis et non ignorés), configurations Release et Debug des sources Windows et Linux. Aucune syntaxe en erreur.

Le périmètre couvre les classes de fenêtres WinForms de `src/app` et `src/plugins`, leurs bases héritées et parties Designer, la ressource C++ askpass, les pages de paramètres et les constructions de fenêtres sans classe dédiée. Les boîtes système sont recensées par site dans le CSV annexe. L’installateur Windows et ses références WiX sont listés séparément, avec leur adaptation au paquet Debian. Les exécutables externes, les tests/démos et les popups internes de bibliothèques tierces ne sont pas comptés comme des fenêtres applicatives portées.

**Recensement exhaustif des types et ressources de fenêtres de ce périmètre ; évaluation par écran, pas audit de chaque bouton ni de toutes les valeurs possibles d’un dialogue.** Une adaptation dans Browse ou un prompt générique n’est pas comptée comme une fenêtre Windows intégralement portée. `N3` ne signifie pas 100 % et aucune entrée n’est `N4`. Les 13 familles de migration du TODO restent ouvertes.

## Lecture des niveaux

- **N0** — Absent : aucun équivalent utilisateur de cette fenêtre/page.
- **N1** — Substitut minimal : prompt, lien externe ou écran très simplifié.
- **N2** — Portage partiel : fonctions substantielles, écarts identifiés.
- **N3** — Fonctionnel ciblé : écran ou adaptation étendue avec tests ; parité totale non certifiée.
- **N4** — Parité complète auditée contre Windows (aucune entrée à ce jour).
- **NA** — Spécifique Windows, sans reproduction directe Linux.
- **BASE** — Classe de support, exclue des comptes des écrans.

Aspect : `rapproche` = disposition/éléments Windows repris sur un périmètre ; `adapte` = interface native différente ; `integre` = fonction dans un autre écran/menu ; `generique` = prompt/UI commune ; `externe` = CLI/navigateur/éditeur ; `systeme` = dialogue du bureau ou adaptation OS. Aucune de ces mentions n’atteste une parité visuelle intégrale.

Validation : les liens de tests signalent des scénarios associés présents dans la suite de référence **997/997 Desktop**, source `aca93bcea`. Ils ne valent pas audit de toute la fenêtre. Les scénarios Plugins explicitement liés sont rattachés à leur lot de référence ; un test du moteur ne valide pas son interface. Les ADR précisent les périmètres natifs acceptés et encore ouverts ; les preuves anciennes ne sont pas transférées à une nouvelle source. Les dialogues recensés `N0` restent absents même si leur moteur ou un contrôle voisin existe.

## Écarts prioritaires révélés par le relevé

- Paramètres : pages absentes ou dispersées, notamment raccourcis configurables, scripts/événements, langue, fontes, outils et intégrations CI.
- Sous-modules : Audit GUI natif exhaustif, DPI/accessibilité et toutes les interactions de DataGridView restent ouverts. Une largeur minimale gauche protège Add ; corrections volontaires des défauts Windows de conflit, worker et restauration de sélection. Assistant de conflit gitlink distinct FormMergeSubmodule non porté. Aucune promesse de transaction contre toutes les mutations externes concurrentes.
- Assistant de conflit de sous-module, sélecteurs de scripts et fenêtres de PR/hébergement absents ; éditeurs de règles désormais présents sur un périmètre ciblé testé.
- Journal Git partiel : métadonnées disponibles, sorties/cache/stacks/export Windows absents.
- Menus View/Navigate : le périmètre récent est testé, mais recherche incrémentale et sélection interactive des parents/enfants restent ouverts.
